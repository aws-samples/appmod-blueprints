# Idempotency — NEVER open a duplicate MR (CRITICAL)\nBefore creating ANY branch or merge request, FIRST call the gitlab tool to LIST OPEN merge requests in the target repo (state=opened) and inspect their titles and changed files. Treat the incident as ALREADY handled if an open MR edits the SAME file you would edit (e.g. `configs/<addon>/values.yaml`) or targets the same addon/component. Multiple alerts for the same component across different clusters are ONE issue, because `configs/<addon>/values.yaml` is cluster-agnostic. When a matching open MR exists: do NOT create another MR or branch — add a short comment on that EXISTING MR noting the extra affected cluster/pod, then STOP. Only open a new MR when NO open MR already addresses that file/component.\n\n
